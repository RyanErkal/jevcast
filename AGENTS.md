# Jevcast

Native macOS launcher and window manager. Swift Package, SwiftUI + AppKit, macOS 14+. Open source (MIT).
Use small focused files. No external dependencies, except libghostty (GhosttyKit) for the Terminal view, built from pinned Ghostty source by scripts/ghosttykit.sh. Keep local actions off network paths.

## Naming

Do not name a feature after a model. "Luna" is one OpenAI model (GPT-6 Luna), not a feature. The writing feature is "Quill". User-facing model names belong in the model picker, not feature names. Code may use model IDs for requests and capability checks. Existing storage identifiers may retain `luna` to preserve settings and keys without a migration.
Reasoning effort and Fast are separate settings. Effort is one of the model's levels (none, low, medium, high, xhigh, max). Fast is an on/off switch for the faster service tier. Never put "Fast" in an effort list.

## Network

Direct service requests are limited to the daily GitHub update check, opt-in Jev matching, opt-in Quill through OpenRouter, opt-in tailnet checks, and the IMAP and SMTP servers of mail accounts the user adds in Settings › Mail. User-initiated Google and Microsoft mail sign-in opens the provider's fixed authorization endpoint in the system browser and uses its fixed HTTPS token endpoint for exchange and refresh. OAuth uses PKCE, state validation, a loopback-only callback, and Keychain tokens. It never follows token-endpoint redirects. Mail resource loading is the separate exception described below.
Tailnet checks (Settings › General › Check tailnet devices, off by default) send GET requests only to the Tailscale addresses (100.64.0.0/10, fd7a:115c:a1e0::/48) of the user's own devices: the Jevcast agent's report, the front page of each shared port, and that page's icon from the same server and port. They also run `tailscale ping` for each online computer. Code refuses any other host, never looks up a name, never follows a redirect, and uses no proxy; HTTPS connects to the address and presents the device's MagicDNS name for the certificate. The device list and this Mac's shares come from the local `tailscale` CLI with fixed arguments. Device actions open fixed `vnc://` links or `.rdp` files, and Taildrop runs `tailscale file cp` with only the files the user picks. The Windows agent (`scripts/tailnet-agent.ps1`) is read only and listens on 127.0.0.1; `tailscale serve` shares it with the tailnet only.
Mail accounts connect only to the servers the user chose, always over TLS (implicit or STARTTLS; never plain text). App passwords and tokens live only in the Keychain; never in files, logs, or errors. Jevcast's mail store (`~/Library/Application Support/Jevcast/Mail`) is owner-only. A server's refusal of a sign-in stops sync instead of retrying, so the account is not locked. Never automatically attach filesystem paths, clipboard text, or audio to model requests. Automation prompts may contain paths the user explicitly supplies or approves.
Mail Delete moves to a uniquely selected Trash folder. For Jevcast's own accounts, Delete in Trash removes that message for good (single press, the user's choice), and Empty Trash or Empty Junk removes exactly the messages it counted after the user confirms that count. Permanent deletes name exact UIDs (UID STORE \Deleted, then UID EXPUNGE of the same UIDs) and need UIDPLUS. Never use mailbox-wide EXPUNGE or CLOSE, and never purge Apple Mail's Trash. Apple Mail is not automatically quit, because its quit settings can purge Trash. Drafts and send states are kept in the owner-only MailComposition folder. Interrupted sends require explicit review before resend; startup never resumes a send. `JEVCAST_MAIL_OFFLINE=1` blocks real mail transports, OAuth network requests, and Mail Apple Events. Mail checks use fake servers and temporary stores.
Selected text, mail content, and dictation transcripts go to Quill only when the user turns on that kind in Settings › AI › Quill. Code checks each request against those switches, and every send is logged without its text.
Automations run CLIs the user installed and signed in to (`claude`, `codex`) or commands the user wrote. Jevcast passes the approved prompt and context to those processes. The CLIs send them to their providers under the user's account. Verify subscription authentication; do not inherit an API-key billing route silently. Quill still uses opt-in OpenRouter access.

## Automations

Automations are Jevcast's own scheduler. The signed `jevcast-runner` helper in the app bundle runs them through `SMAppService`, also while the app is closed. They do not need Codex or another app.
Kinds: a script (argv the user typed or approved), an agent (a prompt run by the signed-in `codex` or `claude` CLI, Codex by default), a script that asks an agent to diagnose only when it fails, or a staged report workflow. A staged workflow runs approved argv only: a preflight script plans, then per item at most one fetch worker and one read-only analyst run in order, then a finish script checks and saves. Jevcast passes the scripts fixed flags only; the planner's handoff is checked data and never chooses a program or an argument. The fetch worker is read only with no shell; its one tool is `jevcast-runner --fetch-tool`, which runs the saved fetch argv for the planned period once and records the result itself. Staged definitions come from a reviewed file through `jevcast-runner --configure`, which never turns anything on.
Agent access is enforced by the CLI, not by prompt text: Codex uses its OS sandbox (`-s read-only` or `workspace-write`, network only when the task allows it) with `--ignore-user-config --ignore-rules`, and `features.multi_agent` and `features.multi_agent_v2` off; Claude uses `--restricted --safe-mode --strict-mcp-config` with a fixed tool list and never gets a command tool. Staged stages also turn off Codex tools that reach outside the sandbox (apps, browser, computer use, plugins, web search); the fetch worker additionally has the shell off and only its one pre-approved MCP tool. Read only is the default. There is no full-access level. Never pass `--dangerously-bypass-approvals-and-sandbox`, `danger-full-access`, or `--dangerously-skip-permissions`, and never pre-approve any tool other than the saved fetch tool. Remove API-key variables from agent runs so they use the subscription, and refuse a Codex run whose `~/.codex/auth.json` holds an API key or no ChatGPT sign-in. Use the model a job names exactly; never fall back to another.
Commands an agent runs inside the CLI sandbox belong to that CLI. Jevcast itself never runs text from a model.
Changes outside the agent's access go through a proposal: JSON with operations from a fixed list, checked by code against user-set roots and recorded file identities, approved item by item, applied by Jevcast code with a journal. Deletes go to the Trash. Undo stops when a file changed; it never overwrites.
Automations stay silent. They alert when a run needs input or approval, or fails or is interrupted (once per distinct error), and, only when the automation alerts on success, when a run has something to show (a ready report, a finished backup). A run with nothing due is quiet. Alerts go only through the Jevcast notch panel. A run counts as shown only when the notch reports the card drawn on screen; queueing is not delivery. Never `osascript` or system banners for automations.
Import from Codex reads `~/.codex/automations` and never writes to it. Imported copies start paused, and one stays blocked while its Codex source is ACTIVE.
Quill tasks that read Calendar, Reminders, or Mail run in the app process, which holds those permissions.

## Safety

Do not execute shell text inferred by a model. Jev may only select known action IDs, and code validates any value it fills. Quill only writes text; it never picks or runs actions. Script tasks run only argv the user typed or approved.
Apple Events use fixed script text; values reach scripts only as arguments. Changes to mail go through Apple Mail, or, for Jevcast's own accounts, through the account's IMAP and SMTP servers. The native store keeps Apple Mail's index layout so one reader serves both. Mail HTML never runs scripts; it loads web images, fonts, and style sheets unless the user turns that off in the mail window (on by default, at the user's request).
Preserve user apps and settings. Do not change Spotlight, Raycast, or Rectangle shortcuts automatically.
The Terminal view (Hyper–T) runs the user's login shell with only what the user types or pastes. Jevcast never writes text into it and never reads its contents.
